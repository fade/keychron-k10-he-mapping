* Keychron K10 HE Configuration

This document tracks custom key mappings for the Keychron K10 HE on Linux/Windows.

** 1. Hyper Key Modification
   The left 'Windows' key (between left Ctrl and left Alt) sends *F13*,
   and the host's XKB keymap turns F13 into =Hyper_L= on =Mod3=.

   I moved Hyper off the keyboard's own Hyper code (=271=, 0x010F) because
   that code is a chord of LCtrl, LShift, LAlt and LGui, so applications
   saw =C-M-S-s= and never a Hyper modifier. F13 is free in every layer of
   this keymap, so the host can give it any meaning without colliding
   with another key.

   - *Target Layers*: Layer 2 (Windows/Linux base) and Layer 3 (Fn), so
     Hyper still works while Fn is held
   - *Target Key*: Column 1, Row 5
   - *Original Code*: =227= (Left GUI)
   - *New Code*: =104= (F13 / 0x0068)

   Set it, and the checksum the Launcher checks, with:
   : python3 fix_keymap.py modified_swapped.json 104

   *Host side*: the =fade:f13_hyper= XKB option, from =~/.config/xkb= in
   the dotfiles. Without it F13 arrives as =XF86Tools= and Hyper does
   nothing.
   - Wayland (libxkbcommon reads =~/.config/xkb= itself): add
     =fade:f13_hyper= to the XKB options, e.g.
     =XKB_DEFAULT_OPTIONS=ctrl:nocaps,shift:both_capslock,fade:f13_hyper=.
   - X: append the symbols to the keymap and load it with the user path:
     : setxkbmap -print | sed '/xkb_symbols/s/"\([^"]*\)"/"\1+fade(f13_hyper)"/' \
     :     | xkbcomp -w 0 -I$HOME/.config/xkb - "$DISPLAY"

** 2. Parentheses & Square Brackets (Fn Layer)
   Layer 3 is a full pre-shifted layer that also relocates the brackets
   onto the number row. It is reached with the *Fn* key, NOT with Shift.

   *Why not Shift:* the K10 HE runs Keychron's Launcher firmware (no QMK
   Key Overrides), so a key cannot both pass a real Shift modifier to the
   OS and produce an *unshifted* bracket. Driving this layer from Shift
   (=MO(3)= on the Shift keys) suppressed the Shift modifier entirely,
   which broke Shift+Enter/Tab, range selection, and function-key chords
   in terminals and GUIs. Shift must therefore stay a real modifier; the
   bracket layer lives on Fn instead.

*** Behavior Table
   The physical =[= =]= keys are mapped directly to parentheses, so parens
   need no Shift. Brackets and braces live on the Fn layer.
| Physical Key | Tap | + Shift | + Fn (Layer 3) |
|--------------+-----+---------+----------------|
| *9*            | 9   | (       | [              |
| *0*            | 0   | )       | ]              |
| *[*            | (   | (       | {              |
| *]*            | )   | )       | }              |

*** Implementation Details
   - *Layer 2 (Win/Linux Base)*:
     - Left Shift: =225= (KC_LSFT) — real modifier, must not be remapped.
     - Right Shift: =229= (KC_RSFT) — real modifier, must not be remapped.
     - Fn (row 5, col 12): =21027= (MO(3)) — momentary access to Layer 3.
   - *Layer 3 (Fn Layer)*:
     - 9 Key: =47= (Left Bracket)
     - 0 Key: =48= (Right Bracket)
     - [ Key: =559= (Left Brace)
     - ] Key: =560= (Right Brace)
     - *Alpha Keys*: Map to shifted equivalents (Base + 512).

** Application Steps
   1. Open the [[https://launcher.keychron.com/][Keychron Launcher]].
   2. Switch keyboard to *Win/Android* mode.
   3. Authorize the device.
   4. In the *Save/Load* tab, click *Load* and select =modified_swapped.json=.

   *Alternatively (Manual VIA)*:
   - Use the *Any* key on Layers 2 and 3 (Col 1, Row 5) to set code =0x0068=.

** Recovery After Factory Reset
   If a factory reset becomes necessary, the Import path in the Launcher
   is sensitive to device state and can silently skip layers if the
   slider position and selected layer tab don't match the file's intent.
   Symptoms of a partial write: the Launcher display shows the swap on
   every layer, but the device only honors it in the wrong slider mode
   (e.g. swap works in Mac/iOS but not Win/Android).

   Reliable sequence:
   1. Factory reset the keyboard.
   2. Open the Launcher and confirm firmware is up to date.
   3. Set the hardware Mac/Win slider to *Win/Android*.
   4. In the Launcher, click the *Layer 2* tab (the target base layer).
   5. Click *Import* and select =modified_swapped.json=.
   6. Wait for "Imported Successfully".
   7. Verify on the physical keyboard:
      - =[= → =(=    and  =]= → =)=
      - Shift+9 → =(=   and  Shift+0 → =)=
      - Fn+9 → =[=     and  Fn+0 → =]=
      - Fn+[ → ={=     and  Fn+] → =}=
      - *Shift is a real modifier:* Shift+Enter, Shift+Tab, Shift+click
        range-select, and Shift+F-keys all work. (If Shift does nothing
        as a modifier, the Shift keys have been left as =MO(3)= — reassign
        Left Shift to =225= and Right Shift to =229= on Layer 2.)

   If any slot fails after Import, click that key in the Layer 2 view
   and manually reassign the keycode — per-click edits write live to
   the active layer and bypass whatever Import state is stuck.

** Project Structure (~/system_scripts/keychron/)
   - =original.json=: Stock keymap backup.
   - =modified.json=: Only contains the Hyper key change.
   - =modified_swapped.json=: Contains both Hyper and Bracket/Parentheses swap.
   - =swap_brackets.py=: Script that generates the complex Layer 3 mapping and re-calculates the MD5 checksum.
   - =fix_keymap.py=: Sets the Hyper key's keycode on Layers 2 and 3 and rewrites the MD5 checksum the Launcher checks.
